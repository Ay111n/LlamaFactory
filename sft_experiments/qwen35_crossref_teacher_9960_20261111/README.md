# Qwen3.5-9B reference-assisted Tibetan teacher

Counterpart to the existing sft-new2 teacher, following teacher_backbone_comparison_20261111/README.md. Uses the frozen crossref_teacher_9960_20261111 data in place: 9,960 pairs, 19,920 examples, 2:1:1 tasks, same 40 held-out diagnostic UIDs, verbatim responses and row order. Fresh LoRA, rank 32, alpha 64, dropout .05, all eligible language-model linear layers; visual tower/projector frozen. Two epochs, batch 1 / accumulation 32, seed 3407, lr 5e-5, cosine schedule, warmup .05.

Qwen3.5 native qwen3_5 template with enable_thinking=false. CPU preflight verifies full input/target sequences and response masking through the actual multimodal processor (text-only examples). Longest sequence 14,472; cutoff 16,384 prevents truncation. Token counts and LoRA parameter counts differ across architectures; matched examples/epochs do not imply matched computation.

User approved adding flash-linear-attention==0.4.1 and fla-core==0.4.1 to training; installed with --no-deps, preserving torch 2.6.0 and transformers 5.2.0. smoke.py performs fresh short/longest-example updates on GPU 0; full training starts fresh from the original base after that check. Runtime evidence and configs are ignored; weights/checkpoints belong to finetuning/model/sft/qwen35_crossref_teacher_9960_20261111.

Run teacher.py preflight --model /home/nlp/data/model/LLM/raw/qwen3.5-9b, then smoke.py with CUDA_VISIBLE_DEVICES=0, then launch.py. The launcher verifies the checks and routes temporary/compiler files to the data partition using the short tmp_q35 path; this avoids the full system partition and AF_UNIX path-length limits. queue only accepts idle GPU 0. No distillation. The separate comparison supervisor merges and runs matched reference-assisted OFF diagnostics after both arms complete.

The native full-vocabulary FP32 cross-entropy allocation OOMed on the longest example. memory_ce.py uses the already installed FlashAttention Triton CE kernel with exactly the same shift, ignore mask, and mean/supplied-denominator reduction. Production-vocabulary FP32/BF16 loss and gradient checks are in runtime/memory_ce_equivalence.json. This is a memory implementation change, not a new learning objective. The full run and longest-example check both use this kernel; sft-new2 keeps its original native CE implementation.

Startup diagnostic: native FLA 0.4.1 backward reproduces the `wy_fast.py:223` Triton encoding error documented at https://github.com/fla-org/hybrid-distillation/issues/2. A no-dependency pip dry run confirms only fla-core and flash-linear-attention would change to 0.4.0. The user subsequently approved the exact rollback. Installation audit confirms only these two distributions changed from 0.4.1 to 0.4.0; torch, Triton and other dependencies remain unchanged. Full training is gated on the renewed standalone backward and longest-example checks. The longest-shape FLA warmup preserves RNG state and runs before loading weights, so compiler failures are caught without repeated model loading. CE uses in-place backward to reduce temporary memory, with the same value/gradient comparison. Runtime dependency_resolution_pending.json records the request and reproduction; dependency_rollback.json records the authorized exact changes.

Validated startup: with approved FLA 0.4.0, the native-shape standalone forward/backward check passed, as did the production-vocabulary CE comparison and full-model two-step check (sequence lengths 524 and 14,472). Peak torch allocation was 45,027,860,480 bytes; both losses and gradient norms were finite. Full training was then launched fresh from the original Qwen3.5-9B on GPU 0 through launch.py. Runtime smoke_passed.json and launch.json are the evidence; this does not yet establish teacher answer quality.

Full attempt 1 failed during step 10 after 9 completed updates: Accelerate tried to cast unused output logits to FP32 (10.21 GiB allocation). No checkpoint had been saved. Evidence and the original trainer log are hash-verified under runtime/failed_full_attempt1 and the model failed_full_attempt1 directory; the disposition manifest is in docs/inventory/qwen35_teacher_retry_20261111. Retry 2 omits only training-output logits before Accelerate conversion, preserves the CE autograd graph and inference/eval logits, and passed exact loss/parameter-gradient comparison on a real tiny Qwen3.5 model. The stress check now uses four longest examples, accumulation 2 and two updates to include accumulated gradients and optimizer state. Expandable CUDA segments are enabled. Full-run logging is every step and checkpointing every 25 steps; data, seed, optimization recipe and 2-epoch budget are unchanged.

Performance diagnosis: `profile_speed.py` runs an isolated three-update paired probe on the same four frozen examples, with microbatch 1 / accumulation 4, one warmup update, one CPU/CUDA-profiled update and one unprofiled hot update. It never exports weights or changes the production run (accumulation 32). Run Qwen first to select examples, then sft-new2. Its output cache directories must not already exist. CUDA `component:*` user-annotation ranges in the raw event list overlap actual kernels and must be excluded when calculating kernel shares; CPU synchronization time also overlaps GPU work. A single hot update is not a stable throughput benchmark. `check_metadata_cache.py` compares fresh versus reused original sequence-boundary tensors for one immutable 3,038-token position tensor using the installed FLA kernel; it checks exact output and all five input-gradient equality and alternates timed runs. This is a bounded feasibility check, not an installed production optimization or full-model acceleration claim. Runtime evidence stays under `runtime/speed_diagnosis/`; no dependency changes.
